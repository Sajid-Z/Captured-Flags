CHALLENGE DESCRIPTION:
----------------------
Ever wondered how emulators tick under the hood? I built one - the simplest of
all, a CHIP-8 emulator. Alongside it, I dropped 100+ games and programs.
Somewhere inside, a flaw is hidden. Trigger it and recover the flag.

Flag format hint: 0xctf{}

FILES PROVIDED:
--------------
- Chip8_Emulator.zip
  - the_Chip8_Emulator/chip8Emulator
  - the_Chip8_Emulator/roms/*.ch8

SOLUTION:
---------

1. INITIAL RECONNAISSANCE
   
   Extracted the archive and inspected the executable:
   - ELF 64-bit PIE, dynamically linked
   - Not stripped (lots of useful C++ symbols)
   - Full RELRO, Canary, NX, PIE
   
   Because symbols are present, reversing is much faster with `nm` + `objdump`.

2. FIND THE HIDDEN EXECUTION PATH
   
   In the CPU dispatcher, `Cpu::decode_F_instruction()` has a hidden case:
   - Opcode `FxFF` calls `Cpu::superChipRendrer()`
   
   This is not a normal CHIP-8 instruction and is clearly challenge-specific.

3. REVERSE `superChipRendrer()`
   
   The routine:
   - Decodes a large embedded base64 blob
   - Uses AES-256-CBC (`EVP_DecryptInit_ex`, `EVP_DecryptUpdate`, `EVP_DecryptFinal_ex`)
   - Uses an internal runtime key (`emu_key`)
   - Writes output into `flag.txt`
   
   So the objective is to reliably invoke `FxFF` in a crafted ROM.

4. UNDERSTAND STATE BEHAVIOR
   
   `Cpu::fetch()` calls `Cpu::cache()` every cycle, and this mutates `emu_key`.
   Therefore, decryption output depends on how many cycles/opcodes are executed.
   Running `FxFF` different numbers of times produces different outputs.

5. CRAFT THE EXPLOIT ROM
   
   A minimal stable payload is:
   - Execute `FxFF` exactly 4 times (quad cycles)
   - Then loop forever so execution does not continue into random bytes
   
   ROM bytes:
   - `F0 FF`
   - `F0 FF`
   - `F0 FF`
   - `F0 FF`
   - `12 08`  (jump to 0x208, i.e., to itself)
   
   Hex:
   `f0ff f0ff f0ff f0ff 1208`

6. RUN AND EXTRACT FLAG
   
   Run emulator headless:
   - `SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy ./chip8Emulator -r solve.ch8`
   
   Then read:
   - `cat flag.txt`
   
   This yields the final flag.

7. RESULT
   
   Vulnerability/feature abused:
   - Hidden non-standard opcode path (`FxFF`) that performs privileged decrypt+write
   - Stateful key mutation across cycles lets us reach the plaintext at the right step count
