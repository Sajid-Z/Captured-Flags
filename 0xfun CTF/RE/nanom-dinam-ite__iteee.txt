SOLUTION:
---------

1. INITIAL RECONNAISSANCE
   
   Started with quick ELF triage:
   - `file` -> 64-bit PIE, stripped binary
   - `checksec` -> Full RELRO, Canary, NX, PIE
   - `strings` -> suspicious embedded line:
     - `Oh sure, here is your flag: 0xfun{1_10v3_M1LF}`
   
   The challenge hint says "Don't trust what you see", so this string is likely bait.

2. OBSERVE REAL RUNTIME BEHAVIOR
   
   Running under `strace` shows this sequence:
   - `fork()` creates child + parent
   - child calls `ptrace(PTRACE_TRACEME)` then `raise(SIGSTOP)`
   - parent uses `waitpid()` / `ptrace()` to supervise execution
   
   So the real validation is happening while the parent silently traces the child.

3. REVERSE THE CHILD CHECK LOGIC
   
   Disassembly of the child routine shows:
   - Reads input as `Pass:`
   - Enforces exact length `0x28` (40 bytes)
   - Uses rolling state seeded with `0xcbf29ce484222325`
   - For each byte, calls a helper update function and then triggers `ud2`
   
   Helper update per byte:
   - `h ^= byte`
   - `h *= 0x100000001b3`
   - `h ^= (h >> 32)`

4. REVERSE THE PARENT "INVISIBLE" VALIDATION
   
   Parent process contains a 40-entry `uint64` table in `.rodata` at `0x20a0`.
   On every SIGILL (`ud2`) trap it:
   - Reads child registers with `PTRACE_GETREGS`
   - Expects `rbx == character_index` (0..39)
   - Expects `rax == expected_hash[index]`
   - If matched, patches child RIP by `+2` (skip `ud2`) and continues
   - If not matched, kills the child / exits

   This means success is not based on printed decoy text, but on hidden per-byte
   state transitions verified by the parent debugger.

5. INVERT THE HASH CHAIN
   
   Because each step is deterministic and depends only on previous state + one byte,
   recover input byte-by-byte:
   - Take previous state `h_prev`
   - For candidate byte `c` in `0..255`, compute `h_next`
   - Keep `c` where `h_next == table[i]`
   - Set `h_prev = table[i]` and continue

   Each position yields a unique byte. Reconstructed 40-byte input:
   - `0xfun{unr3adabl3_c0d3_is_s3cur3_c0d3_XD}`

6. VERIFY
   
   Running binary with recovered input reaches the true success path and prints:
   - `[+] Oh oh sorry, now really this is the flag.`

   So the decoy `0xfun{1_10v3_M1LF}` is fake, and the validated input is the real flag.
