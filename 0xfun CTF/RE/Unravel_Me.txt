0xFun CTF - Unravel Me Writeup

CHALLENGE DESCRIPTION:
----------------------
Someone sent a stripped crackme and claimed it was impossible to reverse.
Hint says normal tools fail and creativity is required.

FILES PROVIDED:
--------------
- crackme

SOLUTION:
---------

1. INITIAL RECONNAISSANCE
   
   Started with `file`, `readelf`, and `strings`.
   Binary is 32-bit ELF, stripped, with a massive `.data` section.
   Useful strings found:
   - "Usage: ./crackme <flag>"
   - "Wrong!"
   - "Correct!"

2. IDENTIFY THE ANTI-REVERSE MECHANISM
   
   Direct execution hangs and repeatedly segfaults.
   `strace`/`gdb` showed signal-driven flow with custom handlers (`SIGSEGV`/`SIGILL`),
   and intentionally broken control transitions (`jmp [0x85fc1d4]` -> null).
   This is a VM-like obfuscation design to break normal dynamic analysis.

3. LOCATE REAL CHECKER REGION
   
   Mapped references to output strings and followed control flow to the checker block.
   The comparison core spans roughly `0x8049a08` to `0x80515a7`.
   Final decision point:
   - accumulator at `0x805304c`
   - compared against zero at `0x80515ac`

4. DEOBFUSCATE LOOKUP TABLES
   
   Decoded major tables from `.data`:
   - `0x8066f30` -> addition table (`a + b`)
   - `0x81a7a80` -> XOR table (`a ^ b`)
   - `0x8197570` -> OR table (`a | b`)
   - `0x81fbb70` -> sign-extension map for bytes
   
   This revealed constant-time style checking:
   - per index: compare input byte to expected byte via XOR
   - fold mismatches into one accumulator via OR
   - pass only when final accumulator is zero

5. USE A HYBRID APPROACH (STATIC + EMULATION)
   
   Because full native execution is intentionally unstable, used a focused approach:
   - Break into checker entry with gdb
   - Snapshot state/memory
   - Emulate only checker region with Unicorn
   - Trace input-byte reads and corresponding XOR operands
   
   This recovered each expected byte in order without relying on the broken runtime path.

6. RECOVERED FLAG
   
   Reconstructed expected string (42 chars):
   `0xfun{r3v_ObfU4C3t10n_m4St3r_246643635876}`

7. VERIFICATION
   
   Verified at compare point `0x80515a7`:
   - with candidate flag, accumulator at `0x805304c` is `0x00000000`
   - check passes (correct path)
