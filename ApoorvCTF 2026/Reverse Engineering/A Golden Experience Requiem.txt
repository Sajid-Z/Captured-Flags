CHALLENGE DESCRIPTION:
----------------------
You thought you had won but then events started happening for which there is
no apparent cause, it seems like the program can see the future

FILES PROVIDED:
--------------
- challenge

SOLUTION:
---------

1. INITIAL RECONNAISSANCE
   
   Running the ELF prints:
   - "loaded flag"
   - "printing flag....."
   
   and then the process crashes/hangs. No visible flag is printed.

2. IDENTIFY THE CORE MECHANISM
   
   Static analysis (objdump/r2) showed a SIGSEGV handler at code offset
   0xb637 and a generated buffer pointer in global memory (0x549a0).
   
   The handler fills 40 bytes in that buffer while repeatedly handling
   deliberate faults, then control is forced to an unmapped page.

3. FIND THE ANTI-ANALYSIS PERTURBATION
   
   A global byte at 0x54991 affects byte generation:
   - if set, generated bytes are offset by +0x37 before XOR mixing
   
   This causes incorrect output during slower/debug runs.

4. DYNAMIC EXTRACTION
   
   Used gdb to:
   - compute PIE base from /proc/<pid>/maps
   - break in the fault handler at offset 0xb6a4 when index == 39
   - patch runtime instructions to neutralize perturbation:
     - b5d9: `cmove eax, ecx` -> `mov eax, ecx; nop`
     - b6d2: `jbe` -> `jmp` (skip +0x37 corruption block)
   - dump the completed 40-byte buffer at r15

5. RECOVERED FLAG
   
   The dumped buffer is direct ASCII:
   - apoorvctf{1_h0pe_5BR_i5_w33kly_rele4as3}

6. VERIFY
   
   Submitted to challenge id 30 via /api/v1/challenges/attempt.
   API response:
   - status: correct
   - message: Correct
