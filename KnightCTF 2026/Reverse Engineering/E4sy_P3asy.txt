## Statement
An easy RE...
Flag Format : KCTF{flag}

## Initial Analysis
First things first, I checked what kind of file I was dealing with using `file` and `strings`.

```bash
$ file E4sy_P3asy.ks
E4sy_P3asy.ks: ELF 64-bit LSB pie executable, x86-64

$ strings E4sy_P3asy.ks | grep CTF
KnightCTF_2026_s@lt
KCTF{
```

The string `KnightCTF_2026_s@lt` stood out immediately. It looked like a salt used for something.

## Static Analysis
I opened the binary in a disassembler to understand the logic. I found the main verification loop pretty quickly.

Here's what I determined the program was doing:
1. It takes the user input (the flag).
2. It loops through the input string character by character.
3. Inside the loop, it validates the flag prefix `KCTF{` and suffix `}`.
4. For the core content of the flag, it constructs a new string using a format that looked like `%s%zu%c`.
   - Before the call to `MD5` related functions (`EVP_DigestUpdate`), it was preparing this buffer.
   - It effectively does: `MD5(salt + index + character)`.
5. It then compares the resulting MD5 hash against a hardcoded list of hashes stored in the binary.
6. There were 23 hashes in total for the inner flag content.

## The Solution
Since MD5 is a one-way hash, I couldn't just "decrypt" the target hashes. However, since it hashes one character at a time, the search space is tiny (just printable ASCII characters).

I extracted the 23 target hashes from the binary and wrote a quick Python script to brute-force the characters one by one.

### Solver Script
Here is the script I wrote to verify my theory and recover the flag:

```python
import hashlib
import string

# Hashes extracted from the binary
hashes = [
    "781011edfb2127ee5ff82b06bb1d2959",
    "4cf891e0ddadbcaae8e8c2dc8bb15ea0",
    "d06d0cbe140d0a1de7410b0b888f22b4",
    "d44c9a9b9f9d1c28d0904d6a2ee3e109",
    "e20ab37bee9d2a1f9ca3d914b0e98f09",
    "d0beea4ce1c12190db64d10a82b96ef8",
    "ac87da74d381d253820bcf4e5f19fcea",
    "ce3f3a34a04ba5e5142f5db272b6cb1f",
    "13843aca227ef709694bbfe4e5a32203",
    "ca19a4c4eb435cb44d74c1e589e51a10",
    "19edec8e46bdf97e3018569c0a60baa3",
    "972e078458ce3cb6e32f795ff4972718",
    "071824f6039981e9c57725453e005beb",
    "66cd6098426b0e69e30e7fa360310728",
    "f78d152df5d277d0ab7d25fb7d1841f3",
    "dba3a36431c4aaf593566f7421abaa22",
    "8820bbdad85ebee06632c379231cfb6b",
    "722bc7cde7d548b81c5996519e1b0f0f",
    "c2862c390c830eb3c740ade576d64773",
    "94da978fe383b341f9588f9bab246774",
    "bea3bb724dbd1704cf45aea8e73c01e1",
    "ade2289739760fa27fd4f7d4ffbc722d",
    "3cd0538114fe416b32cdd814e2ee57b3"
]

salt = "KnightCTF_2026_s@lt"
flag = ""
chars = string.printable

print("Cracking...")

for i in range(len(hashes)):
    for c in chars:
        # Replicate the binary logic: salt + index + char
        combined = f"{salt}{i}{c}"
        m = hashlib.md5(combined.encode()).hexdigest()
        if m == hashes[i]:
            flag += c
            break

print(f"Recovered Flag: KCTF{{{flag}}}")
```

## Result
Running the script confirmed my analysis. The output was:

```
Cracking...
Recovered Flag: KCTF{_L0TS_oF_bRuTE_foRCE_:P}
```

I verified it against the binary and it was accepted!
