CHALLENGE DESCRIPTION:
----------------------
"is really? again six seven?"
Format: 0xfun{}

FILES PROVIDED:
--------------
- six-seven-revenge.gz (contains chall, libc.so.6, ld-linux-x86-64.so.2, libseccomp.so.2)
- Dockerfile

SOLUTION:
---------

1. INITIAL RECONNAISSANCE

   The binary is a simple note manager with Create/Delete/Read/Edit.
   Protections: PIE + Full RELRO + Canary + NX. No direct GOT overwrite.
   The size limit is 0x500, so heap exploitation is the intended path.

2. BUGS IDENTIFIED

   - Use-after-free via stale pointer usage on a freed note.
   - Null-byte overflow in Edit allows us to shrink the next chunk size.
   - Safe-linking is present, so tcache poisoning must respect the heap key.

3. LEAK THE SAFE-LINKING HEAP KEY

   Create/free a 0x30 note, then re-allocate and read back the freed chunk
   contents. The low byte is clobbered by our input, so recover the heap key
   by combining two leaks (tcache fd and encoded pointers) and enumerating the
   256 low-byte candidates. The correct candidate yields valid chunk offsets.

4. BUILD A UAF + CONSOLIDATION LIBC LEAK

   - Allocate chunk A and B (size 0x2e8) with a guard chunk after them.
   - Use Edit on A to null-byte overflow B.size to 0x2f0 and craft a fake
     header inside A to satisfy consolidation checks.
   - Free B: it consolidates with A and leaves a dangling pointer in the
     notes array, giving us a UAF read of the unsorted fd.
   - Unsorted fd leaks main_arena, so libc base = fd - 0x1e7b20.

5. Tcache Poisoning FOR ARBITRARY READ/WRITE

   With A_user address known (heap key), use the UAF note to overwrite the
   tcache fd with target ^ (heap_key). This allows controlled allocations
   anywhere and gives arbitrary read/write primitives.

6. LEAK STACK (ENV + AUXV) AND POINTER GUARD

   - Read libc.__environ to find the stack address.
   - Walk nearby stack windows to parse auxv; extract AT_RANDOM and AT_ENTRY.
   - Compute PIE base from AT_ENTRY and recover the pointer guard from the
     AT_RANDOM buffer (mangled pointer protection).

7. HIJACK EXIT WITH LONGJMP + ROP

   - Build a fake jmp_buf on the heap (mangled rbp/rsp/rip).
   - Poison __exit_funcs to call longjmp(arg) with our heap buffer as arg.
   - ROP chain performs open("/flag" or "flag.txt"), read, write to stdout.

8. GET FLAG

   Trigger Exit in the menu. The process longjmps into the ROP chain and
   prints the flag.
