CHALLENGE DESCRIPTION:
----------------------
Find the input that produces: 0x4C494D494E414C21
Wrap your answer in 0xfun{}

FILES PROVIDED:
--------------
- liminal (ELF 64-bit LSB executable, x86-64, stripped)

SOLUTION:
---------

1. INITIAL RECONNAISSANCE

   The binary reads an 8-byte (uint64) input and produces an 8-byte output.
   The target output 0x4C494D494E414C21 decodes to the ASCII string "LIMINAL!"
   in big-endian. Disassembly reveals a heavily unrolled structure: 64 near-
   identical "gadget" blocks, each computing one output bit via cache timing,
   plus a bit permutation and round-key XOR repeated across 8 rounds.

2. IDENTIFY THE CIPHER: SUBSTITUTION-PERMUTATION NETWORK

   The binary implements a classic SPN block cipher with 8 rounds:

       state = input ^ key[0]
       for round 0..6:
           state = sbox_substitute(state)
           state = bit_permute(state)
           state ^= key[round + 1]
       state = sbox_substitute(state)    // final round, no permutation
       return state

   Each substitution step applies 8 independent byte-level S-boxes (one per
   byte of the 64-bit state). Each S-box lookup is performed by 8 gadgets
   (one per output bit), giving 64 gadgets total.

3. UNDERSTAND THE SPECTRE SIDE-CHANNEL MECHANISM

   Each of the 64 gadgets uses a Spectre-variant side-channel to compute
   its output bit via cache timing rather than direct arithmetic:

   a) FLUSH: Two probe addresses r8 and r9 are flushed from cache. For
      gadget g: r8 = probe_base + g*0x480, r9 = probe_base + g*0x480 + 0x240.

   b) SPECULATIVE ACCESS: A trampoline function misaligns the Return Stack
      Buffer (RSB) by pushing a different return address and flushing the
      original. On ret, the CPU speculatively returns to the gadget body
      while the correct address resolves from memory. The gadget body
      speculatively loads probe_base + table[input_byte], where the table
      value is either 0x100 or 0x340.

   c) RELOAD: After a NOP sled (serialization window), the gadget times
      access to r8 and r9 using rdtscp. Whichever region was speculatively
      touched will be faster to access, revealing the table value and thus
      the output bit.

   d) CONFIDENCE: The gadget repeats 50 times across a calibration loop,
      accumulating a majority-vote confidence score.

   Mapping: table value 0x340 falls in r9's region [0x240, 0x480) → bit=1.
            table value 0x100 falls in r8's region [0x000, 0x240) → bit=0.

   The key insight is that the cmp/setb instruction compares the two probe
   timings: setb sets the bit to 1 when r9 is faster (i.e. r9 was cached,
   meaning the speculative access went to the 0x340 region). Therefore
   0x340 → 1 and 0x100 → 0.

4. EXTRACT CIPHER PARAMETERS FROM THE BINARY

   All cipher data lives in the .data section (VA 0x40a000, file offset 0x9000):

   - 64 lookup tables at VA 0x40f280, each 256 × uint64 (0x800 bytes per table).
     Every entry is either 0x100 (bit=0) or 0x340 (bit=1).

   - Bit permutation table at VA 0x42f280: 64 bytes, perm[i] = source bit
     for output bit i. Verified to be a bijective permutation of 0..63.

   - 8 round keys (uint64) at VA 0x42f2c0:
       key[0] = 0xeff230922b8f2f34
       key[1] = 0xb7acc594df2767b4
       ...
       key[7] = 0xbfc90d85da8f9378

5. BUILD AND INVERT THE S-BOXES

   For each of the 8 S-boxes (s = 0..7), combine the 8 corresponding gadget
   tables (g = s*8..s*8+7) to construct a 256→256 byte mapping. Each table
   contributes one bit per input byte. All 8 S-boxes are verified to be
   bijective (full permutations of 0..255), confirming unique invertibility.

6. COMPUTE THE ANSWER

   With all components extracted, implement the full SPN decrypt:
   - Apply inverse S-boxes to the target ciphertext
   - For each round (in reverse): undo the key XOR, invert the bit
     permutation, and apply inverse S-boxes
   - XOR with the first round key to recover the plaintext

   decrypt(0x4C494D494E414C21) = 0x4c8e40be1e97f544

   Verification: encrypt(0x4c8e40be1e97f544) = 0x4C494D494E414C21 ✓

7. BINARY PATCHING (SUPPLEMENTAL VERIFICATION)

   Because the Spectre cache side-channel does not work reliably on all
   hardware (timing noise yields random confidence, calibration frequently
   fails), a patched binary was created to verify the solution. In each of
   the 64 gadgets, the 81-byte timing section (clflush/rdtscp/cmp) was
   replaced with a deterministic comparison:
       sub %rsi, %rdx      ; rdx = table[byte] - probe_base
       xor %eax, %eax
       cmp $0x240, %rdx    ; 0x340 >= 0x240 → bit=1; 0x100 < 0x240 → bit=0
       setae %al
   The calibration loop call was patched to an unconditional jump (skip).
   The patched binary confirms: compute(0x4c8e40be1e97f544) = 0x4C494D494E414C21 ✓
